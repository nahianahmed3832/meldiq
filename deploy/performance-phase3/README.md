# Handoff rehearsal

Use the [report](../../docs/performance-phase3/REPORT.md) and [decision](../../docs/performance-phase3/decision.json) before doing anything on the live host. These tools do not grant authority to replace the writer.

The isolated Docker harness targets `/opt/griip-internal-messaging/releases/phase3-lab`. It creates a new unpublished network namespace, a private PostgreSQL instance, a restricted six-session fixture role and temporary data. Only owned, labeled containers are removed. Fenced exclusive ownership, actual health checks, encrypted peer traffic and database readbacks are required. `fixtures.mjs BACKEND WEB STATUS NEW_DIRECTORY` verifies the 15 migration files and bootstrap by hash, compiles the reference clients from source, and packages the monitor helpers. Use the candidate backend checkout, the web Supabase migration sources and the Meldiq status source. The backend operator branch includes the two monitor helpers used by the lab. The status pair runtime is private and is never part of the bundle.

The normal-entry test uses the actual pinned image's `dist/index.js`, a separate private control mount, fixture-only identities, file mail and a loopback database. `standby-boot.mjs` waits at the writer boundary after the normal preflight. It requires a fresh per-slot nonce and deadline; its private control channel is not a public API. The instrumented lab imposes only additional delay on faster database reads. `certify-host.py` checks healthy production identity and shared-host capacity, then invokes the isolated lab. Do not use the owned client, fixture environment or calibration adapters as production startup commands.

For an off-host native reproduction, separately compile the pinned incumbent, candidate and rollback with their existing TypeScript configuration. Supply their three compiled server directories and the generated fixture directory to `native-lab.py FIXTURES OLD NEW FALLBACK OUTPUT`. Its PostgreSQL, Redis, API and clients all bind to loopback; failed runs retain only synthetic diagnostics. Native timing does not replace the container gate.

`evaluate.py RECEIPTS` reads evidence and emits a decision; it never promotes a service. Live admission needs fresh measurements, no existing direct clients, adequate restricted-role headroom, no operator maintenance, unchanged release locks/checkpoints and a ready fallback before stopping the incumbent. If an incumbent or managed connection vetoes a switch, leave that session connected and defer; never terminate it to obtain a passing gate. Confirm release-specific normal boot jobs, authority receipt, configuration and live p95 before promoting. Existing direct connections cannot be moved retroactively by an nginx reload.

The opt-in ingress commands `prepare / restage / activate / rollback / check / retire` are restricted to the matching release checkpoint on the operator host. `ingress-cycle.py` uses the configured isolated two-member DM and always restores the original route. Do not export its private cohort header or fixture credentials. All public ingress measurements in this report used the original digest of the ingress recorded by the prepare receipt. The later managed-session drain veto was tested in staging.
