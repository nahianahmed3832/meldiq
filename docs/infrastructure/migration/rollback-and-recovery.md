# Recovery

Before the writer switch, Singapore is the application authority. Keep the SQL/Mongo authority, local fallback, object stores and version manifests intact. Disable the optional MEDIA_PUBLIC_BASE_URL to restore the existing authenticated download path if the edge release fails. Restore nginx from the retained /opt/meldiq-web/storage-migration-headers-20261103T065311Z backup only if the installed clients no longer need the new origins. Restore the prior storefront release as an atomic link switch if necessary.

After the writer switch, a region-variable change can strand Frankfurt-only files or restore deleted media. First fence new uploads, multipart completion, retention/deletion jobs and writers in every API instance. Drain or explicitly preserve in-flight upload sessions; their presigned URLs and upload IDs belong to their original region. Keep both buckets readable. Confirm the authoritative database and a usable current backup. Run deploy/storage-migration/rollback-plan.py with the exact forward and disk journals. It refuses unexpected source changes or missing Frankfurt history. Follow the reverse-delta JSONL per key in order. Copy the specified Frankfurt versions into Singapore preserving metadata/tags, hash and compare bytes. Reproduce necessary soft markers only after reviewing their impact. Never hard-delete an existing version. Reconcile the database's live file references and disk fallback under the fence before reopening traffic. If a store is inaccessible or a manifest is inconsistent, keep the surviving writer authoritative until the delta can be recovered.

The read-only reverse plan produced zero post-baseline entries at staging. No production writer reversal was rehearsed. The forward copier does not run against an active Frankfurt writer. Preserve the manifests and test the reverse plan again after any new writes. Do not remove Singapore data without separate explicit authorization.
