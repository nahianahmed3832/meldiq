# Client compatibility

| Platform | Release inspected | Works without a release? | Evidence and limits |
|---|---|---|---|
| Web | Deployed 0.5.0-beta-supabase-prep-8bda737 | The browser origin checks pass with the same build after the host update. | Chromium on the live page initially emitted CSP violations for both target origins. The nginx headers and signed-download proxy allowlist were extended under the release lock. nginx validation passed and the same browser probe reported neither origin blocked. Authenticated full-path testing is separate. |
| Windows | Public Windows 0.2.0 x64 installer, SHA-256 6e53a63f4953fa7a5650865deacf5e8a45b377d60fcfad1c08582486b9383313 | No for direct Frankfurt multipart uploads. | Downloaded the actual 124,227,227-byte installer, verified its hash, extracted app.asar and launched its main process/renderer using the matching Electron runtime on macOS. Requests to both new origins triggered CSP violations. The candidate reads exact HTTPS connect-src origins from its trusted web host. The candidate payload passed the same checks. Native Windows CI built, installed, launched and uninstalled its development installer. Stable-feed qualification is tracked separately. |
| Android | Public Play listing for com.meldiq.android. Local Android sources report 0.5.5. Local 0.5.3 release receipt explicitly says unsigned and not Play-published. | No source change identified. Production binary result is unverified. | The uploader consumes backend-signed URLs, including separate parts. Attachment JVM tests passed. Three Android instrumentation tests passed on the API 36 emulator. These are source/debug tests. A store listing and an unsigned bundle do not identify an installed production build. |

Windows 0.2.0 retains the old fixed origin in its installer. Its single-file fallback does not rescue an interrupted multipart transfer to a blocked host. Keep the old path available until installed-client and upload-session transition risks have been addressed. Small-file success alone cannot qualify a cutover. No Android update or web build was forced.
