# Account thread-follow synchronization

Candidate source only; not deployed. Community follows and explicit opt-outs use the existing native thread endpoints and current history/membership authority. They do not change channel membership. Direct-chat and older-server preferences retain their local behavior.

`GET /v1/me/thread-preferences` returns this account's accessible preferences in pages, including `following: false`. Clients must finish pagination before replacing a cached snapshot, retain the previous projection on failure and reject a snapshot overtaken by a newer account event or choice. `thread.preference` updates the current profile without issuing another PUT. Other accounts do not receive these preference events.

An explicit user choice uses `PUT /v1/threads/:id/follow` with `{ "following": true | false }`. Omitting the new option preserves existing behavior. Clients must keep an explicit opt-out separate from a missing positive follow: participation history must not silently restore ordinary thread Activity or notifications. Direct mentions retain their existing notification policy.

Servers advertising `thread-follow-import` also accept optional `ifUnset: true`. This imports an old local choice only when no preference exists for that account/root. The check and write share the existing native thread lock and authoritative transaction. An existing choice, including false, is returned without changing its timestamp or emitting another preference event. The response's `following` may therefore differ from the import request. A concurrent explicit opt-out wins regardless of which operation takes the lock first.

An older client does not send the option; a newer client must not send it to a server that lacks the capability. Imports must retain current thread history/membership/deletion checks. Unknown or inaccessible legacy roots must not be guessed to be public community threads. Profile changes, late responses, partial pages, reconnects and interrupted imports require client qualification; source contracts alone do not establish installed-device acceptance.
